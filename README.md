# Varde

Mobile development management for AI-assisted developers. Varde is a native Android command center for developers who coordinate work from their phones.

See [product vision](docs/VISION.md) and [roadmap](docs/ROADMAP.md).

## Build
Use JDK 17, Android SDK 35 and Gradle 8.9. Run `GH_CLIENT_ID=your_client_id gradle :app:assembleDebug`. The public client ID is required for login; never embed a client secret. Enable Device Flow in the GitHub OAuth app. This initial client requires non-expiring access tokens; expired or revoked sessions require sign-in again.

CI builds a debug APK. Private repository access requires the broad OAuth repo scope, requested only when explicitly selected at login. Organization policies may restrict access.

## Mobile workspace

Open a repository for its README and docs, recent commits, open issues and pull requests, changed files, conversation and review comments, check runs, workflow runs, jobs, logs, releases, and repository files (including images and files over 1 MB). Lists load every page up to a limit and say when more exist. Long job logs show their last 200 KB, where failures usually are.

**Review and act.** Comment, approve, request changes, comment on a specific diff line, mark a draft ready for review, update a branch that is behind, close, and merge with the methods the repository allows. Rerun failed jobs, cancel a running workflow, start a workflow by hand, disable a workflow or delete a run. Draft or publish a release, with notes generated by GitHub. Every GitHub write is confirmed first; if the connection drops mid-write, Varde says the outcome is unknown instead of offering a retry.

**Inbox.** Review requests, failing PR checks, failed workflows on each repository's default branch, reviews of your own pull requests, recent mentions, assigned work and delegated tasks. Partial loads, rate limits and result limits are reported, never shown as an empty inbox.

**Handovers.** Briefs include repository instructions (AGENTS.md, CLAUDE.md) verbatim plus the screen's evidence. Share or copy them, or send them to an agent that works from GitHub: post them to an issue or pull request for `@claude` or `@copilot`, assign an issue to Copilot's coding agent, or open a new issue for either. That needs the Claude GitHub app or Copilot's coding agent set up for the repository. Tracked handovers are followed in the Inbox until their pull request is ready.

**Storage and privacy.** Settings can exclude repositories. Pins, groups and the portfolio stay in app-private storage per account. GitHub responses are cached in a size-capped cache for offline use and when GitHub is rate limited or failing; cached screens show when they were saved, logs are never cached, and every cache is cleared on sign-out. Optional background checks (Settings → Notifications) poll GitHub about every 30 minutes over WorkManager, using conditional requests; the first check only records existing items, and nothing is sent anywhere except GitHub. Optional on-device assistance (Settings → On-device assistance, off by default) uses Gemini Nano through ML Kit on supported phones to draft handover tasks, rewrite review comments and suggest log lines; repository instructions and tracking IDs never pass through the model, and ML Kit is only started while the feature is on.

## Installing builds

A repository's **Install a build** page lists APKs attached to its latest release and app builds uploaded by its workflow runs, newest first, for the default branch and for other branches and pull requests (a pull request page links straight to its own builds). Varde downloads the artifact, unzips it, shows which app and version is inside, and hands it to Android's installer, which asks for confirmation. Android must first allow Varde to install apps. Artifacts that don't look like app builds are hidden until you choose **Show all artifacts**; one that turns out to hold an APK is remembered for that repository.

## Releases

See [Releasing Varde](docs/RELEASING.md): publishing a release builds a signed, shrunk APK and attaches it to the release.

## Debug APK updates

CI numbers each build (`versionCode` is the workflow run number) and signs debug APKs with the public debug-only key in `app/debug-keystore.b64`. This allows subsequent APKs from this workflow to be installed as updates while retaining local data and the encrypted GitHub session. APKs signed with an older runner-generated key cannot be upgraded in place; uninstalling once removes local data and requires a fresh sign-in. The included key is public and is never appropriate for release signing.
